# 서라벌여중 ㄱ자형 학교 리뉴얼 — 적용 및 검증 보고서

기준 자료: 이번 작업에 첨부된 `sewol-port-rpg-school-renewal(1).zip`, `붙여넣은 텍스트(1)(5).txt`, `교과서102-103페이지(4).docx`.

> **중요한 정확도 경고:** 실제 학교 1~4층의 원본 실측 교실배치도 및 학교 외관 원본 사진은 이 작업 턴의 첨부물에 포함되지 않았습니다. 따라서 이번 결과물은 텍스트에 명시된 **학습지원실2를 기준으로 왼쪽 구간이 90도 꺾이는 ㄱ자 구조**와 층별 방 목록을 기반으로 만든 **게임용 재배치안**입니다. 개별 방의 정확한 실측 순서, 방향, 실제 계단·엘리베이터 수평 위치는 확정·검증하지 않았습니다.

## 구현된 변경 사항

- `school.py`를 층별 공간 데이터의 단일 출처로 개편. 각 공간에 ID, 화면 이름, 층, 꺾인 동/가로 동, 실제 게임 출입 지점과 문패 표시 지점을 저장.
- 1층 15개, 2층 14개, 3층 13개, 4층 12개, 총 **54개 공간**을 게임에 등록. 안내서에 명시된 학습지원실1·2, 보건실, 행정실, 과학실1·2·3, 기술실, 가정실, Wee클래스, 음악실1·2, 국어도서관 등을 포함. 계단과 중복되지 않는 개별 출입 좌표 사용.
- 17개 학급 및 담임교사 이름·교과 정보를 기존 데이터 키 그대로 유지. 각 반 5개 조사 요소, 특별실 3개 조사 요소 유지.
- 기존 가로 일자형 복도를 **ㄱ자형 충돌 데이터와 두 동을 연결하는 코너 통로**로 교체. 복도 밖 벽과 정원 영역을 통과할 수 없음.
- 교실의 출입·퇴장 위치, 층별 계단, 목표 교실 내비게이션이 동일한 학교 데이터에 연결됨. 잘못된 직선 화살표를 제거하고 BFS 통행 경로의 다음 칸을 화살표에 표시.
- 모든 공간의 이름은 `name`/`display_name` 기준으로 복도에서 가까운 문패 확대 안내, 층별 안내도, 실내 헤더, 입장 안내에 표시. 긴 이름이 60px 문패에 잘리는 문제를 회피하기 위해 **약식 번호 문패 + 가까이서 전체 이름** 방식을 사용.
- 마을의 학교 간판에 남아 있던 `서라벌여자중학교` 문자열을 `서라벌여중`으로 교체.
- 기존 게임 스택, 6개 마을 구역, 16개 사건, 저출산·고령화와 생애설계, 성인·노년기 단계 전환, 저장 스키마 `1`, 기존 Google Sheets 연동 코드를 **수정하지 않고 계승**.
- `tools/generate_lschool_assets.py`를 추가하여 ㄱ자 복도 4개 레벨과 ㄱ자 학교 외관 PNG를 프로젝트 전용 절차적 픽셀 아트로 직접 생성. `tools/validate_assets.py` 및 `frontend/assets/manifest.json`의 프레임·경로 검증 필드 보강.
- `tools/browser_smoke.py`를 확장하여 학교 ㄱ자형 길찾기, 전체 54개 문까지의 경로, 학습지원실2의 진입·원위치 복귀, 1→3층 계단, 교사 이벤트 기록·복원, 모바일 방향키의 길게 누르기를 브라우저에서 검증.

Playwright 테스트는 Streamlit 서버가 아니라 HTML/CSS/JS와 이미지를 **격리 브라우저에 인라인 삽입**해 실행한 스모크 테스트입니다. 서버를 통한 통합 앱 실행으로 표시하지 않습니다. 첨부된 PNG 스크린샷도 이 격리 브라우저에서 실제 Canvas를 캡처한 결과물로, 콘셉트 이미지가 아닙니다.

## 현재 한계 및 다음 적용 순서

1. **실제 학교 도면을 받으면** 54개 공간의 날개별 방향과 정확한 순서를 확인하고 `school.py`의 `ROOM_ORDER`와 문 좌표를 수정해야 합니다. 현재 특별실의 소품·실내 구조는 주제별 장식이 들어간 공용 배경에 가까우며, 실제 교실·특별실의 크기와 가구를 재현한 상태가 아닙니다.
2. 학교 외관은 ㄱ자 실루엣과 붉은 벽돌, 4개 층, 녹색 정문 울타리를 절차적 픽셀 그래픽으로 묘사한 **1차 시안의 실제 게임 에셋**입니다. 제공 이미지와 동급 이상의 고밀도 수작업 타일/애니메이션 퀄리티까지 완성했다고 주장하지 않습니다.
3. 방마다 3~5개 조사 기록은 되지만, 54개 모든 공간의 서로 완전히 다른 이벤트나 실측 기반 인테리어·개별 교사 일과는 추가 제작이 필요합니다.
4. 기존 저장 데이터의 `room_id`, `school_records`, `guide_mode`, `schema`를 유지하여 서버 기록과 충돌하지 않도록 했지만, 이전 세션에 저장된 구 복도 좌표는 통행 가능 영역을 검사해 복원하거나 기본 입구로 되돌립니다. 좌표 저장은 기존 방식대로 브라우저 sessionStorage 기반입니다.
5. Streamlit 앱 실행, 실제 시트 쓰기·복원, 교사 대시보드, 실기기 터치, 20분 완료율은 배포 환경에서 반드시 별도로 검증해야 합니다.

## 개발자용 재현 방법

```bash
pip install -r requirements.txt
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m compileall -q app.py engine.py content.py school.py storage.py
node --check frontend/game.js
python tools/validate_assets.py
python tools/browser_smoke.py
streamlit run app.py
```

특히 `tools/generate_school_assets.py`는 이전 버전의 기본 학교 에셋 생성기입니다. **이번 ㄱ자형 에셋만 다시 만들려면** `python tools/generate_lschool_assets.py`를 사용하세요.
